# 科研周报：记忆可靠性判别与 VLM 选型

**汇报日期：2026年10月27日**

## 一、不可靠记忆的分类与已有判别方法

本项目将记忆可靠性问题细分为以下六类，分别检查“描述是否矛盾、描述是否有依据、位置是否准确、物体身份是否对应、记录是否过期、任务信息是否充分”。这是一种工作分类，几类问题可以同时出现；信息不足也不一定意味着记忆有错。

| 类别 | 核心问题 | 简单例子 |
|---|---|---|
| **① 内容与图像矛盾** | 记忆描述是否与图片里的事实相符？ | 图片里是蓝杯子，却记成红杯子。 |
| **② 描述缺乏图像支持** | 记下来的这句话有图像依据吗？ | 杯口被遮住，却写了“装着咖啡”。 |
| **③ 空间定位错误** | 物体的位置记对了吗？ | 杯子在桌子左侧，记忆坐标却落在右侧。 |
| **④ 实例关联错误** | 多次看到的是同一个具体物体吗？ | 把两只相似杯子的记录合并成同一只。 |
| **⑤ 时间失效／记忆过期** | 过去的记录对当前时间还成立吗？ | 杯子原来在桌上，后来被搬走。 |
| **⑥ 当前任务信息不足** | 现有信息够完成这次任务吗？ | 只记了“有杯子”，无法判断哪只装水。 |

以下只介绍判别依据。部分论文还包含记忆修正、观察选择等内容，此处仅提取其中与判别有关的部分。判别结果需区分“发现矛盾”“存在风险”和“证据不足”。

---

### 1. 内容与图像矛盾

**具体情况：** 来源图片中有较清楚的证据，能够看出记忆描述不符。例如花盆被记成杯子、蓝杯子被写成红杯子，或者物体明明在桌上，却写成“在椅子上”。问题出在当初的识别或描述，而不是物体后来发生了变化。

**已有判别方法：**

```text
1. 逐条检查图文是否一致——FaithScore。把描述拆成“有杯子”“杯子是红色”“杯子在桌上”等小事实，分别与来源图片核对，检查是否存在不一致。原论文评价模型生成内容，将其用于存储记忆是本项目的适配。
2. 检查同一物体的跨视角描述是否矛盾——UQ-DAAAM。比较多个视角的描述，如果类别、颜色、材质等反复变化，就用语义分歧给出不确定性分数。这只能筛出可疑内容，不能仅凭分歧认定哪条描述错误。
3. 检查模型回答是否稳定——VL-Uncertainty。对问题或图片做不改变原意的扰动，再比较回答在含义上的变化；回答越不稳定，幻觉风险越高。但多次回答一致，也可能是模型一直认错。
```

**对应论文：**

- **FaithScore: Fine-grained Evaluations of Hallucinations in Large Vision-Language Models** — Findings of EMNLP 2024，**2024年11月**。
- **Remember with Confidence: Uncertainty Quantification for Spatio-temporal Memory with Probabilistic Guarantees**（UQ-DAAAM）— **NeurIPS 2026，已接收**；arXiv 首发 **2026-06-06**。
- **VL-Uncertainty: Detecting Hallucination in Large Vision-Language Model via Uncertainty Estimation** — arXiv 预印本，**2024-11-18**。

### 2. 描述缺乏图像支持

**具体情况：** 记忆已经作出了某个判断，但来源图片没有提供足够依据。例如杯口被挡住，却记录“杯子里没有水”；物体背面没有拍到，却描述了背面的图案。这些话可能碰巧是真的，但现有图片证明不了。与第一类的区别是：第一类有证据显示不符，这一类主要是缺少支持证据。

**已有判别方法：**

```text
1. 检查每条陈述是否有图像依据——参考 FaithScore。先将描述拆成可核对的小事实，再逐条检查图片是否支持。例如“杯子里装着咖啡”，需要图像中能够辨认杯内内容，不能仅凭杯子的外观推断。
2. 区分“图像反驳”与“图像无法确认”——本项目在事实核验上的适配。看见杯内是空的，才有依据反驳“装着咖啡”；杯口被遮挡时，只能认为缺乏支持。FaithScore 提供事实级图文核验思路，这种细分状态并非其原生保证，需另行设计和验证。
```

**对应论文：**

- **FaithScore: Fine-grained Evaluations of Hallucinations in Large Vision-Language Models** — Findings of EMNLP 2024，**2024年11月**。

---

### 3. 空间定位错误

**具体情况：** 物体本身认对了，但记忆中的坐标或空间位置不准。例如杯子确实在桌上，坐标却落在桌外；或机器人定位发生偏差，使整片物体记录的位置都偏了。若当初坐标正确、后来物体被搬走，则属于第五类“记忆过期”。

**已有判别方法：**

```text
1. 检查历史位姿与优化位姿是否一致——DREAM。比较建立记忆时使用的相机位置、朝向，与后续 SLAM 优化后的结果；平移或旋转差超过阈值时，标记相关历史观测存在位姿不一致，提示其物体坐标可能不准。
2. 检查多视角几何位置是否一致——参考 ConceptGraphs。利用深度和相机位姿，把同一物体的不同观察放到统一坐标系，检查三维重合程度。明显对不上可以作为空间风险线索，但也可能来自关联错误或物体移动，不能直接确定原因。原论文提供几何匹配依据，将其用于已有记忆的位置检查需要适配。
```

**对应论文：**

- **Dynamic Resilient Spatio-Semantic Memory with Hybrid Localization for Mobile Manipulation**（DREAM）— arXiv 预印本，**2026-05-30**。
- **ConceptGraphs: Open-Vocabulary 3D Scene Graphs for Perception and Planning** — **ICRA 2024**；arXiv 首发 **2023-09-28**。

---

### 4. 实例关联错误

**具体情况：** “实例”就是某一个具体物体。这类问题是不同观察与具体物体的对应关系搞错了。例如先后拍到两只相似的红杯子，却把它们当成同一只；或者从正面和侧面拍到同一只杯子，却记成两只。这里关注的是“是不是同一个东西”，而不只是“是不是同一类别”。

**已有判别方法：**

```text
1. 联合检查外观与空间匹配——参考 ConceptGraphs。比较不同观察的视觉特征相似度，以及三维位置的重合程度，用两方面证据判断它们是否可能属于同一物体，避免仅凭“都是红杯子”就认定为同一个实例。
2. 检查已有对应关系是否得到匹配证据支持——基于 ConceptGraphs 的项目适配。对已经归入同一物体的观察，检查几何与外观匹配是否明显不足；证据不足时将该关联标为可疑。原论文主要进行物体关联，并不是现成的错误关联诊断器；具体诊断规则和阈值需验证。
```

**对应论文：**

- **ConceptGraphs: Open-Vocabulary 3D Scene Graphs for Perception and Planning** — **ICRA 2024**；arXiv 首发 **2023-09-28**。

### 5. 时间失效／记忆过期

**具体情况：** 当初没有看错、位置也没有记错，但环境后来变了。例如昨天杯子在桌上，今天被搬到柜子里；继续用旧记录回答“杯子现在在哪”，就可能出错。有效性需要对照问题所指的时间：回答“昨天在哪”时，昨天的记录仍可能有效。

**已有判别方法：**

```text
1. 无新观察时，预测原位置仍有效的概率——PreSIST。根据物体本身、场景和经过的时间，估计它仍停留在原位置的可能性。这一步给出过期风险，不能直接证明物体已移动。
2. 已有新观察时，检查原位置的深度证据——OmniNav。将记忆中的物体表面投影到当前深度图，区分“原表面仍在”“原位置已空”“被更近的东西挡住”，据此估计记忆位置仍有效的概率。遮挡不能直接等同于物体消失。
3. 检查旧记录与当前可见空间是否矛盾——DynaMem。如果深度观测清楚显示，记忆中物体所在的位置实际是空的，就得到旧几何记录不再适用的线索。这里仅采用深度射线的一致性检查依据。上述位置持续性方法主要判断物体是否仍在原位，门是否打开、杯子是否装水等属性变化，还需另行检查。
```

**对应论文：**

- **PreSIST: Vision-Language-Informed Object Persistence Prediction in Open-World Scenes** — arXiv 预印本，**2026-07-04**。
- **OmniNav: Robust Long-Horizon Target Navigation in Dynamic Environments** — arXiv 预印本，**2026-09-08**。
- **DynaMem: Online Dynamic Spatio-Semantic Memory for Open World Mobile Manipulation** — **ICRA 2025**；arXiv 首发 **2024-11-07**。[

### 6. 当前任务信息不足

**具体情况：** 现有记忆可能全部正确，但缺少这次任务所需的信息。例如只记录“桌上有两只杯子”，无法完成“找出装水的那只”；也可能有多个符合描述的候选，现有信息不能确定是哪一个。与第二类的区别是：第二类检查“已经写出的判断有没有依据”，这一类检查“现有信息够不够完成任务”。

**已有判别方法：**

```text
1. 对照当前问题，检查证据是否充分——Sufficient Context。将问题和检索到的内容交给充分性评估器，判断现有信息能否支持明确答案，而不只是看它们是否相关。例如“有杯子”与找杯子相关，但不足以回答“哪只装水”。原方法面向文字 RAG，应用于图文记忆需要适配。评价仅针对当前提供的证据，信息不足不能直接证明整个记忆库没有相关记录。
2. 检查支持证据与观察覆盖——SafeVantage。综合支持该判断的视角、不同视角的空间一致性和已观察范围，评估证据能否支持肯定或否定判断。例如“没看到杯子”可能只是没看全。原论文主要验证类别是否存在，扩展到颜色、状态和关系等问题需要适配。
```

**对应论文：**

- **Sufficient Context: A New Lens on Retrieval Augmented Generation Systems** — **ICLR 2025**；arXiv 首发 **2024-11-09**。[论文与会议信息](https://proceedings.iclr.cc/paper_files/paper/2025/hash/33dffa2e3d2ab74a783d1a8c292f66d9-Abstract-Conference.html)
- **SafeVantage: Vantage-Aware Memory for Reliable Embodied Decisions** — arXiv 预印本，**2026-09-29**。[论文](https://arxiv.org/abs/2609.36906)

## 三、相近研究 AMV-Guard 与暂定的方向对比


**论文：** *When Is a Memory Safe Enough to Act On? Action-Conditioned Verification for Long-Lived Agents*（方法名：**AMV-Guard**）。

**状态：** arXiv 预印本，首发于 **2026年10月22日**


**AMV研究的问题：** 记忆可能不可靠时，智能体怎样决定先核验、直接执行还是放弃，并控制核验成本。

**我暂定的研究的问题：** 沿用 ReMEmbR 建库与检索，面对可能不可靠的记忆，在预算内决定重看旧图、去现场核验、直接导航或继续搜索，以较低总成本找到目标。
