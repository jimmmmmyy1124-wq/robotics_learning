### 2. 附加任务2：Python 自定义 A* 路径规划器

本阶段的主要工作是将原本由 Nav2 默认全局规划器完成的路径规划部分替换为自主实现的 A* 算法。

自定义规划器主要完成：

- 使用 `rclpy` 编写 ROS 2 Python 节点；
- 订阅 `/map`，读取 `nav_msgs/OccupancyGrid`；
- 将 ROS 地图转换为二维 A* 栅格；
- 通过 TF 获取机器人在 `map` 坐标系下的当前位置；
- 通过 RViz2 `Publish Point` 获取用户点击目标；
- 将起点和终点由世界坐标转换为地图栅格坐标；
- 使用 Python 实现 A* 搜索；
- 将最终栅格路径转换为 `nav_msgs/Path`；
- 将自定义路径发布到 `/astar_path`；
- 在 RViz2 中显示自定义 A* 路径；
- 通过 Nav2 `FollowPath` Action 将路径交给 DWB Controller 执行。

整体结构为：

```text
RViz2 Publish Point
        ↓
/clicked_point
        ↓
自定义 A* Planner
        ↓
/map + TF
        ↓
A* 栅格搜索
        ↓
nav_msgs/Path
      ↙      ↘
/astar_path   FollowPath Action
    ↓              ↓
 RViz2       Nav2 Controller
                    ↓
                 /cmd_vel
                    ↓
               TurtleBot3
```

与之前任务四的 `NavigateToPose` 不同，本任务中 Python 节点不再只是向 Nav2 提供目标点，而是直接生成完整路径，因此能够验证自定义规划算法与 Nav2 控制部分之间的集成。

### 3. A* 算法实现与路径安全处理

A* 使用：

```text
f(n) = g(n) + h(n)
```

其中：

- `g(n)` 为起点到当前节点的实际累计代价；
- `h(n)` 为当前节点到目标点的启发式估计；
- 本任务的 `h(n)` 使用欧氏距离。

规划器采用 8 邻域搜索：

```text
↑  ↓  ←  →
↖  ↗  ↙  ↘
```

水平和垂直移动代价为 `1`，斜向移动代价为 `sqrt(2)`。

为了避免斜向路径直接穿过障碍物墙角，在斜向扩展时增加了额外检查：如果斜线两侧的横向或纵向相邻栅格存在障碍，则禁止该次斜向移动。

在障碍物安全距离处理方面，最终采用：

```text
硬障碍膨胀
+
障碍物附近软代价
```

当前硬膨胀半径为 3 个栅格。由于地图分辨率为：

```text
0.05 m/cell
```

对应约：

```text
0.15 m
```

同时利用障碍物距离生成额外软代价，使 A* 在空间允许时优先选择离墙体和障碍物更远的路径，又不会因硬膨胀过大而直接封死门口等狭窄区域。

### 4. 自定义路径与 Nav2 Controller 集成

A* 输出最初为栅格路径：

```text
[(x0, y0), (x1, y1), ..., (xn, yn)]
```

程序将路径点重新转换为世界坐标，并生成：

```text
nav_msgs/Path
```

路径发布到：

```text
/astar_path
```

同时根据相邻路径点方向计算每个 Pose 的 `yaw`，再转换为四元数，使路径点朝向与实际前进方向保持一致。

随后创建：

```python
ActionClient(
    self,
    FollowPath,
    'follow_path'
)
```

将自定义 `Path` 发送到 Nav2 Controller Server。

因此最终职责划分为：

```text
自定义 A*
    ↓
负责全局路径生成

Nav2 DWB Controller
    ↓
负责实际路径跟踪和速度控制
```

## 三、遇到的问题及解决情况

### 1. RGB-D 摄像头初始安装位置不合理

现象：

RGB-D 摄像头加入机器人模型后，初始显示位置与车体存在偏差，视觉上出现摄像头位于车体前方、与机器人本体安装关系不合理的问题。

处理方式：

重新检查摄像头与机器人之间的相对位姿设置，调整传感器安装位置，使摄像头与 TurtleBot3 模型保持合理的固定关系。

---

### 2. A* 斜向路径存在穿墙角风险

现象：

初始八邻域 A* 仅判断目标栅格是否可通行时，斜向路径存在从障碍物墙角附近穿过的可能。

处理方式：

增加斜向移动合法性检查，同时检查斜线两侧的两个相邻栅格；任意一侧不可通行时，禁止该次斜向扩展。

---

### 3. 路径在门口附近过于贴墙

现象：

单纯追求栅格最短路径时，A* 可能生成靠近墙体的路径；如果直接增加较大的硬膨胀，又会明显压缩门口的可通行空间。

处理方式：

将安全策略调整为“较小硬膨胀 + 障碍物软代价”。硬膨胀保证最低安全距离，软代价用于引导路径在有空间时主动远离墙体。

---

### 4. FollowPath 返回状态与机器人实际目标距离不一致

现象：

调试过程中曾出现 Nav2 `FollowPath` 已经返回结束状态，但机器人仍未真正到达用户点击目标的情况。

处理方式：

在 Python 节点中增加独立的实际距离判断，通过 TF 获取机器人当前位置，并与 A* 最终目标坐标计算欧氏距离，不再只依赖 Action 返回状态判断是否真正到达。

---

### 5. 自定义 A* Path 与 Nav2 TF 时间源不一致

现象：

Nav2 日志中出现：

```text
Transform data too old when converting from map to odom
```

进一步排查发现，自定义 A* 节点最初使用系统时间生成 `Path` 时间戳，而 Gazebo、Nav2 和 TF 使用 `/clock` 仿真时间，两者时间体系不一致。

处理方式：

启动自定义 A* 节点时增加：

```text
--ros-args -p use_sim_time:=true
```

使 `astar_planner.py` 与 Gazebo、Nav2、TF 使用同一套仿真时间，解决路径时间戳与 TF 时间不一致的问题。
